# Subagents: delegation rule and digest-docs skill · mode: interactive · human: Mike

## Context
Mike wants Claude to act as its own harness on large tasks: decide for itself when a piece of work
is contained (input → output), spawn agents for it, and pick model and effort. He is wary of
hard-coding fixed agent types. Recurring need: condensing many documents (e.g. old chatbot logs)
into one need-to-know document without filling the main context.

## DECISION: a rule in global CLAUDE.md, not fixed agent definitions
`~/.claude/CLAUDE.md` gained "Subagents: delegate contained work, keep the judgment": when to
delegate, what stays with the orchestrator (scientific choices, interpretation, plan changes,
living docs), briefs as the agent's whole context, outputs to files, spot-check before docs/,
briefs and model/effort named in the log. No `~/.claude/agents/*.md` yet; add one only when a
pattern recurs and needs enforced tool limits (e.g. a verifier with no Edit/Write).

## DECISION: model/effort tiers are written out explicitly
The Agent tool only sets `effort` when instructions explicitly ask for a level, so CLAUDE.md
maps task kinds to levels: haiku/low mechanical, sonnet/medium reading+summarizing, opus/high
synthesis and verification, fable only on request or after opus fails. Claude classifies the task.
Prices from the claude-api skill (cached 2026-11-03), $/MTok in/out: Haiku 5.5 0.10/0.50,
Sonnet 5.5 2/10, Opus 5.5 4/20, Fable 5.2 8/40, Fable 5.1 10/50.

## DECISION: digest-docs as a skill
`skills/digest-docs/SKILL.md`: purpose first (who reads the digest), inventory without reading,
convert structured exports by script, batch 50–150k tokens, parallel extraction to notes with
source pointers and current/superseded status, chat-log assistant claims marked unverified unless
confirmed, merge by a separate agent, verify by a different agent against originals (≥15 claims
or 10%), keep briefs/notes for audit. A skill, not a hard rule: Claude invokes it when it fits.

## Not verified yet

- Whether the `haiku`/`sonnet`/`opus`/`fable` aliases resolve to the 5.x models on Mike's plan.
A first real digest-docs run (or a loop smoke test that must delegate) settles these.
